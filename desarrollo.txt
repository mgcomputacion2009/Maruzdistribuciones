### 🏆 FUNCIONALIDAD COMPLETA: SISTEMA DE RANKING PERSONALIZADO POR USUARIO
**Fecha:** 1 de septiembre 2024  
**Estado:** IMPLEMENTADO  
**Descripción:** Sistema inteligente de posicionamiento de productos basado en el historial de búsquedas de cada usuario

#### 🎯 CONCEPTO DEL SISTEMA:

**"Los productos que más buscas aparecen automáticamente primero"**

- **Cada búsqueda del usuario** se registra automáticamente
- **Productos más buscados** aparecen en las **primeras posiciones**
- **Sin cambios visuales** - solo reposicionamiento inteligente
- **Sistema transparente** - el usuario no sabe que está personalizado

#### 🗄️ ESTRUCTURA DE BASE DE DATOS IMPLEMENTADA:

**Tabla: `ranking_productos_cliente`**
```sql
├── id (AUTO_INCREMENT PRIMARY KEY)
├── cliente_id (ID del usuario - FK usuarios.id)
├── producto_id (ID del producto - FK productos.id)
├── score_ranking (Puntuación personalizada DECIMAL(10,4))
├── ultima_busqueda (Timestamp de última búsqueda)
├── frecuencia_busqueda (Contador de búsquedas INT)
└── Índices optimizados para consultas rápidas
```

#### ⚙️ ALGORITMO DE RANKING IMPLEMENTADO:

**Fórmula:** `Score = (Frecuencia × 0.7) + (Recencia × 0.3)`

- **Frecuencia (70%):** Cuántas veces ha buscado ese producto
- **Recencia (30%):** Qué tan reciente fue la última búsqueda
- **Máximo 30 días:** Búsquedas más antiguas pierden relevancia
- **Actualización automática:** Cada búsqueda recalcula el score

#### 🔧 COMPONENTES IMPLEMENTADOS:

**1. Backend (Python/Flask):**
- **Endpoint modificado:** `/api/autocomplete` registra búsquedas
- **Función:** `registrar_busqueda_ranking()` - guarda cada búsqueda
- **Función:** `calcular_score_ranking()` - algoritmo de puntuación
- **Consulta SQL modificada:** ORDER BY con ranking personalizado

**2. Frontend (JavaScript):**
- **Variable global:** `window.userId` disponible en productos
- **Autocompletado:** Envía `cliente_id` en cada búsqueda
- **Sin cambios visuales:** Mantiene exactamente la misma apariencia

**3. Base de Datos (MySQL):**
- **Tabla de ranking** con índices optimizados
- **Relaciones FK** con usuarios y productos
- **INSERT ... ON DUPLICATE KEY UPDATE** para eficiencia

#### 📊 FLUJO DE FUNCIONAMIENTO:

**Flujo Completo:**
1. **Usuario busca "bujía"** → Autocompletado muestra sugerencias
2. **Sistema registra** búsqueda en `ranking_productos_cliente`
3. **Score se actualiza** según frecuencia y recencia
4. **Usuario entra a productos** → Query ORDER BY ranking personalizado
5. **Bujías aparecen primero** automáticamente en su vista

### 📊 ESTRUCTURA DE BASE DE DATOS

#### **Tabla: `pedidos_activos`**
```sql
├── id (AUTO_INCREMENT PRIMARY KEY)
├── cliente_id (ID del usuario logueado - NULL si es anónimo)
├── session_id (UUID único para usuarios anónimos)
├── producto_codigo (Código del producto)
├── cantidad (Cantidad seleccionada)
├── precio_unitario (Precio por unidad)
├── descuento (Porcentaje de descuento)
├── total_linea (Total calculado con descuento)
├── fecha_agregado (Timestamp de creación)
├── fecha_actualizado (Timestamp de última modificación)
└── estado ('activo' para carrito, 'cerrado' para pedidos finalizados)
```

#### **Tabla: `historial_pedidos`**
```sql
├── id (AUTO_INCREMENT PRIMARY KEY)
├── pedido_id (Número único del pedido - formato: PED-YYYYMMDD-XXXXXXXX)
├── cliente_id (ID del usuario logueado - NULL si es anónimo)
├── session_id (UUID de la sesión anónima)
├── total_pedido (Total del pedido con IVA)
├── cantidad_productos (Número de productos en el pedido)
├── fecha_creacion (Timestamp de creación del pedido)
├── fecha_cierre (Timestamp de cierre del pedido)
├── estado (pendiente, confirmado, cancelado)
└── notas (Información del cliente y detalles del pedido)
```

#### **Tabla: `historial_productos_pedido`**
```sql
├── id (AUTO_INCREMENT PRIMARY KEY)
├── pedido_id (Referencia al pedido en historial_pedidos)
├── producto_codigo (Código del producto)
├── cantidad (Cantidad pedida)
├── precio_unitario (Precio por unidad al momento del pedido)
├── descuento (Descuento aplicado)
├── total_linea (Total de la línea con descuento)
└── fecha_creacion (Timestamp de creación)
```
